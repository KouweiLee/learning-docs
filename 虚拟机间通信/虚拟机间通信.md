# 虚拟机间通信

## jailhouse-调研

jailhouse通过PCI虚拟设备实现通信机制，本质其实就是共享内存加虚拟机间中断。

参与通信的cell可以有2个以上，这些cell都需要在配置文件中声明该PCI IVSHMEM设备的相关信息，例如设备的bdf值，共享内存的位置等。cell访问该设备配置寄存器空间会陷入hypervisor，由hypervisor解析执行操作。

设备的Bar0指向设备寄存器。cell可以将vector号（不使用MSIX就是0）、IVSHMEM设备ID（其实是另一个Cell）写入其中的中断触发寄存器，hypervisor收到后，会写GICD_ISPENDR寄存器，设置该设备对应的中断为pending状态。另一个cell的CPU就会收到该中断，注入自身进行处理。

Bar1为MSI-X。

Bar2指向共享内存区域的首地址。为了防止不参与通信的cell进行破坏，参与通信的每个cell的配置文件中，均需包含共享内存的地址信息，例如：

```c
/* IVSHMEM shared memory regions (demo) */
		{
			.phys_start = 0x7faf0000, // pa
			.virt_start = 0x7faf0000, // ipa
			.size = 0x1000,
			.flags = JAILHOUSE_MEM_READ | JAILHOUSE_MEM_ROOTSHARED,
		},
		{
			.phys_start = 0x7faf1000,
			.virt_start = 0x7faf1000,
			.size = 0x9000,
			.flags = JAILHOUSE_MEM_READ | JAILHOUSE_MEM_WRITE |
				JAILHOUSE_MEM_ROOTSHARED,
		},
		{
			.phys_start = 0x7fafa000,
			.virt_start = 0x7fafa000,
			.size = 0x2000,
			.flags = JAILHOUSE_MEM_READ | JAILHOUSE_MEM_ROOTSHARED,
		},
		{
			.phys_start = 0x7fafc000,
			.virt_start = 0x7fafc000,
			.size = 0x2000,
			.flags = JAILHOUSE_MEM_READ | JAILHOUSE_MEM_ROOTSHARED,
		},
		{
			.phys_start = 0x7fafe000,
			.virt_start = 0x7fafe000,
			.size = 0x2000,
			.flags = JAILHOUSE_MEM_READ | JAILHOUSE_MEM_WRITE |
				JAILHOUSE_MEM_ROOTSHARED,
		},
```

共享内存区域每个部分的意义：

```
+-----------------------------+   -
|                             |   :
| Output Section for peer n-1 |   : Output Section Size
|     (n = Maximum Peers)     |   :
+-----------------------------+   -
:                             :
:                             :
:                             :
+-----------------------------+   -
|                             |   :
|  Output Section for peer 1  |   : Output Section Size
|                             |   :
+-----------------------------+   -
|                             |   :
|  Output Section for peer 0  |   : Output Section Size
|                             |   :
+-----------------------------+   -
|                             |   :
|     Read/Write Section      |   : R/W Section Size
|                             |   :
+-----------------------------+   -
|                             |   :
|         State Table         |   : State Table Size
|                             |   :
+-----------------------------+   <-- Shared memory base address
```

1. 状态表区域（State Table）：只读，表示各个cell是否可通信
2. 可读可写区域（R/W Section）：所有Cell均可读可写该区域，允许大小为0。如果大小不为0需要额外做好互斥机制。
3. 输出区域（Output Section）：假设有3个参与通信的cell，那么就有3个输出区域，第0个输出区域对cell 0可读可写，对其他cell只读。第1个输出区域对cell 1可读可写，对其他cell只读。依次类推。本质上是一种互斥机制。

位于用户态的应用程序可以通过mmap获取到PCI IVSHMEM设备，以及共享内存。具体如何利用共享内存通信由用户自定义，jailhouse反正提供了共享内存和中断机制。

## bao-调研

bao支持两个虚拟机点对点的通信。通过IPI通知对方虚拟机，通过共享内存进行通信。

不同于jailhouse直接使用RAM的固定区域作为共享内存，bao的共享内存由hypervior分配。

bao只有一个全局的配置文件，该配置文件中指定每个vm的共享内存的IPA、大小、中断号：

```c
// vm1:
.ipc_num = 1,
.ipcs = (struct ipc[]) {
    {
        .base = 0x80100000, // ipa
        .size = 0x1000,
        .shmem_id = 0,
        .interrupt_num = 1,
        .interrupts = (irqid_t[]) {42}
    }
},
```

应用程序通过写内核模块，内核模块将信息存储在共享内存，并通过hypercall通知hypervisor，hypervisor会向除了该VM的CPU以外，拥有共享内存的另一个虚拟机发送IPI中断。另一个虚拟机收到中断后，会将配置文件中指定的中断注入给自己，由内核模块完成中断的处理。

应用程序通过读内核模块，由内核模块从共享内存中获取信息。

例如，向某个虚拟机发送信息：

```
echo "Hello, Bao!" > /dev/baoipc0
```

读信息:

```
cat /dev/baoipc0
```

## shyper-调研

shyper之前的一个版本中，是通过共享内存允许虚拟机之间传递文件：

<img src="https://mdpics4lgw.oss-cn-beijing.aliyuncs.com/aliyun/image-20240923142838824.png" alt="image-20240923142838824" style="zoom:50%;" />

特点是：

1. 由hypervisor根据配置文件分配共享内存
2. 共享内存区域有一个标志位，表示当前状态，例如正在写、正在读、是否结束等，保证两个虚拟机对共享内存的互斥访问和操作次序。
3. VM0开始发送时，会通过Hypervisor注入中断给VM1。VM1发送signal唤醒正在睡眠的通信进程，双方开始发送和接受数据。

## 思路

关键问题：

1. 虚拟机间通信的场景：应该要求多个虚拟机一起通信。
2. 虚拟机间如何初始化通信机制
3. 虚拟机之间通信的流程

想把通信跳板的共享内存机制，和虚拟机通信机制，统一起来。通信跳板的双方: Virtio daemon和hypervisor，hypervisor可以伪装成一个vm1。

root linux的设备树，看到的RAM，中一部分可以是假的，是二阶段地址翻译控制的non root memory，也可以是用于IPC的共享内存。然后应用程序通过mmap来获取共享内存，直接通信。根据通信协议，即可避免通信过程中产生中断。

虚拟机之间的互斥机制：是一个发送方，一个接收方。

共享内存建立到什么程度，是要传递文件、还是什么。

还有一个关键问题，应用程序得好用通信机制。

一些小思考：

1. virtio bridge的区域建立现在是root linux内核干的，hypervisor其实可以干。

2. 用 memremap 函数 将分配给自身用于 IVC 的 IPA 映射到内核地址空间。

3. 能否取消root linux的dts需要包含non root 的mem，而是让root linux通过memremap，获得一片IPA内存。IPA和PA由hvisor之前建立映射关系。测试一下，看看memremap能否正常完成工作。

   ### memremap用法

   ```c
   void *memremap(resource_size_t offset, size_t size, unsigned long flags)
   ```

   映射一段物理地址[offset, offset+size]到内核虚拟地址空间，且为缓存地址。flags指定具体缓存的行为。

   对于缓存行为要和ram一样的设备内存，flags指定为*MEMREMAP_WB*。

   **答案:**经过测试，其实不需要memremap，用户态只需要remap那个函数就可以获取到非RAM但其实是RAM的内存。
